Setting up on a cluster

On any cluster with Slurm, HOPE Labs sets itself up in one folder you choose and installs the tools you tick. A tool counts as installed once a real job has run with it.

What a cluster needs

  • Slurm, and an account on it that can queue a GPU job.
  • A login node that reaches the internet. Every download happens there. The compute nodes need no internet at all: the tools are built to work without it.
  • A folder with room, in scratch or in a group folder if others will use it too. HOPE Labs itself takes about 125 MB and 7,000 files; Boltz-2 about 16 GB and 95,000 files; ADCP docking about 5 GB and 60,000 files. Most clusters cap the number of files as well as the space, and Set up checks both before it starts.

Nothing else. No administrator, no modules and no conda: Set up brings its own package manager (micromamba, a single file) and makes its own Python. Nothing is written to your home folder.

Signing in to another cluster

In the HOPE Labs window choose Other (SLURM), then type the cluster's address and your username on it. The password and any second step (a phone approval, a code) are asked in the cluster's own words, as on Grace. A key in your .ssh folder is tried without being named. A key kept anywhere else goes in the SSH key box, and a cluster reached through a gateway takes it in the Gateway box, as host:port.

The first time

At sign-in the launcher looks for a HOPE Labs of its own in every space you have on the cluster: your scratch, each group you belong to, and any work or project folder. One it finds is used, and your computer remembers it. Only when there is none does the Tools page ask.

It then lists those spaces with the room and the number of files each has left, from the cluster's own quota where it has one. A space that already holds HOPE Labs has Use the HOPE Labs here; any other you can write to has Set up here, which fills in the folder below. Your home folder is listed but never offered: a tool alone takes more files than a home folder allows. A space with fewer than 100,000 files left is marked, because most tools need more.

  • Set HOPE Labs up here. Name a folder; the box suggests one in your scratch. HOPE Labs copies its own code there, fetches the package manager and makes a Python for its pages. It takes about a minute, and the page shows each step.
  • Use this one. If you or your group have set it up already, name that folder instead.

Either way, your computer remembers the folder for this cluster, so it is asked once. Then Choose the tools to install opens the Set up page in a tab of its own. Later it is in the rail on the left, as Set up this cluster.

The Set up page

1. This cluster

Read the cluster asks Slurm which partitions there are, how long each will run a job, which cards are in each, and which of them you may use. That last answer comes from Slurm testing a job without queueing it, so a partition that would quietly send a job somewhere else, or refuse it, is marked as one you cannot use.

The page then proposes where GPU jobs go, which card they ask for, and where short CPU steps go. Change any of them and press Save these. They are written to cluster.json in the HOPE Labs folder, and every page on this cluster reads them from then on: the Boltz-2 page's Card menu is the cards this page found.

Ask a GPU node queues a one-minute job that reports the cards, their driver and whether a compute node can reach the internet. The first install asks for itself, because the driver decides which build of PyTorch the GPU nodes can run.

2. Tools

Tick the tools you want and press Install the ticked tools. Each row says how much room it takes, roughly how long, what it needs from the cluster and under what licence it comes. While it installs, the row shows each step as it is reached.

The install runs on the login node in a process of its own. Closing the page, the launcher or the laptop does not stop it; sign in again later and the page shows how far it got. If it stops part way, after a failure, a press of Stop or a login node restarting, Install again carries on from the step it reached: nothing already downloaded is fetched twice.

The last step is the check. Set up queues a real fold on the GPU partition, written by the same code the Boltz-2 page writes its jobs with, and looks at what comes back. Installed and checked means that fold finished and left a structure; the row says where it ran and how long it took. Check again repeats it, which is worth doing after a cluster changes its drivers.

For ADCP docking the check is a docking on the CPU partition: the p53 peptide into MDM2, with a search far too small to mean anything and big enough to run every stage of a real run, the receptor's preparation, the docking and its MM-GBSA, and the report.

Remove takes an installed tool off again, to give its room and its files back: its own folders are deleted, and nothing else. Runs already made are kept, because they are in your runs folders rather than in the tool's, and so are the package manager and its download cache, which every tool shares. Remove only takes what Set up installed; a copy it found already there is left alone. Install puts the tool back whenever it is wanted.

Set up installs Boltz-2 and ADCP docking today. The other tools are listed with whether they are there; their own instructions are in Installing by hand, and they join this page one at a time.

3. What the install is doing

Everything each step printed, as it happens. The same log is kept in the HOPE Labs folder, in setup/logs.

What goes where

<folder>/HOPE-labs        the code: the pages, the flows and Set up itself
<folder>/cluster.json     what the cluster has, as read and confirmed
<folder>/tools/           the package manager
<folder>/envs/hopelabs    the Python the pages run on
<folder>/envs/boltz       Boltz-2, with its weights in envs/boltz/cache
<folder>/ADCP_docking      ADCP docking's code, with the activate.sh that names its tools
<folder>/envs/adcp        its environment: RDKit, AmberTools, PDB2PQR, OpenMM
<folder>/tools/docking     the ADCP 1.1 suite, from Scripps
<folder>/setup/           each install's state, its log and its checks

It is the layout every HOPE Labs folder has, which is why the launcher finds every tool in it without being told where each one is.

Which build of PyTorch

The GPU nodes' driver decides. The CUDA 13 build needs a driver from 580 up and no longer runs on cards older than Turing (a V100, say). The CUDA 12.6 build runs on any driver from 525 up. Set up reads the answer from the GPU check and chooses; the log says which and why.

When an install stops

  • Not enough room. The first step says how much is needed and how much is free. Free some, or set HOPE Labs up in a folder with more.
  • A download was cut off. Press Install again: the download carries on from where it stopped.
  • The check fold failed. The row quotes the end of the job's log, and the whole run is in setup/checks. The usual causes are a partition or card the account may not use (change it under This cluster and press Check again) and a cluster that wants an account named on every job (fill in Account for the check jobs).
  • Something is already there. If envs/boltz holds an install Set up did not make, Set up leaves it alone and says so. Move it aside to install here.

From a terminal

Everything the page does can be done on a login node by hand, which is also how to set HOPE Labs up without the launcher. With the code in the folder:

sh HOPE-labs/hope_labs/setup/bootstrap.sh /scratch/you/hope-labs
cd /scratch/you/hope-labs/HOPE-labs
../envs/hopelabs/bin/python3 -m hope_labs.setup probe --save
../envs/hopelabs/bin/python3 -m hope_labs.setup install boltz2
../envs/hopelabs/bin/python3 -m hope_labs.setup status

install follows the log in the terminal until the check has passed; with --detach it carries on in the background, as it does from the page. remove boltz2 takes it off again.
