When something goes wrong

HOPE Labs says what it found, in a sentence. The common ones, what they mean, and what to do.

Signing in

What you seeWhat it means, and what to do
The password is refused, though it is rightCheck that the NetID box holds your NetID alone. HOPE Labs cuts an email address at the @ and says so in the log, but anything else in the box is sent as it is.
No Duo push arrivesDuo's question is shown exactly as Grace sent it. If it offers a numbered list, answer with the number for a push, as you would in a terminal.
Could not connect: and a reasonThe sign in failed where the reason says. Show technical details is turned on for you, and what it shows is what to send with a report.

The page

What you seeWhat it means, and what to do
The page did not openPress Open the page in the HOPE Labs window, or paste the address the log printed into your browser.
Open this page from the launcher window: it carries the token that gates it. The address was typed or kept without its token. Use Open the page; the token changes every time you sign in.
Chrome blocked the tab.Allow pop-ups for the page once: see Let its tabs open.
The log says the usual port was busyAnother program had it. Nothing is wrong, but Chrome treats the new address as a new site and may ask once more.
A tool's page stopped answeringThe tool was stopped, it stopped by itself, or the connection dropped. Launch it again, after signing in again if the connection is gone.

Starting a tool

When a tool stops before it is ready, its tab says why, with the tool's own last lines under it where they help, and a Try again button. In each sentence the tool and the folder are named.

The sentence beginsWhat to do
HOPE Labs is not set up on this cluster yetNo HOPE Labs was found in any of your spaces, so no tool, flow or report can start from it. The Tools page offers to set it up, or to name the folder it is in if you or your group set it up somewhere else.
there is no tool on the clusterThe folder HOPE Labs looked in does not exist. Install the tool from the Set up page, or by hand, or check that a path you set really spells your folder: Pointing HOPE Labs at your copies.
tool is installed at folder but its activate.sh is missingRun that tool's install.sh again; it writes the file. This is HOPE-MD.
tool is run from a page that is part of HOPE Labs, and the HOPE Labs install on the cluster is not where it is expectedRFdiffusion, RFdiffusion3, BoltzGen, Boltz-2 or ColabFold. The folder named is the HOPE Labs checkout, not the tool's own install, so look there and not at the tool. A checkout somewhere HOPE Labs was not told of is named on the Tools page, or with HOPELABS_INSTALL: The tools whose page is ours.
the quoted lines end in no Python of 3.8 or newer was found for tool's pageThe same tools. Their page is Python, and a login node's own python3 here is 3.6, so one is looked for rather than named outright. Name the one to use with HOPELABS_PYTHON.
tool was not found in its installIts environment loaded, but the tool itself would not import there. Run the tool's own check, or its installer, again.
the cluster ran tool with a Python too old to parse itIts environment did not load, and the login node's own Python ran it. Its activate.sh is not naming the install's own Python.
the port tool was given is takenSomething took the port in the moment between HOPE Labs finding it free and the tool starting. Try again; it is given another.
permission denied starting toolUsually a folder you cannot read, such as an install in a group folder you are not in.
tool did not report a URL within 120sA cold login node can be slow; try again. If it happens again, the tool's own lines quoted under it say why.
tool stopped before it was readyNone of the above; the tool's own last lines are quoted under it.

Results

What you seeWhat it means, and what to do
No run folders yet.None of the folders Results looks in holds a run yet, or the runs are somewhere else: What is listed names where it looks.
A run you know is there is missingResults lists the twelve newest in each folder, and keeps what it read for twenty seconds. Press Refresh.

Reporting a problem

Turn on Show technical details in the HOPE Labs window and copy what is under What is happening. Send it, with what you were doing, to whoever looks after HOPE Labs on your cluster.

Telling somebody

Send feedback, at the bottom of the rail, is there for anything at all: something awkward, something missing, something wrong. On a flow card that failed there is a Report this beside it, which is the same thing with the run already in it.

What usually arrives when something breaks is "the flow failed", and then three messages asking for a job id, a folder and a log. So the report gathers those on the cluster where they are: what you typed, the state of every card, what Slurm says about each job, the last eighty lines of the log, and the settings the card was given. You see the whole of it before anything is written, because it quotes your own run, and you can copy it instead of sending it. Nothing leaves the cluster: it goes to the reports folder beside the HOPE Labs install, for whoever looks after it.
