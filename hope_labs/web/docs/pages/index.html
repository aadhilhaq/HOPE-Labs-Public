HOPE Labs

One front for a set of tools for designing, folding and simulating molecules on a cluster. Sign in once, pick a tool, and it opens in a tab of its own: the page it always was, reached through one connection and one Duo approval.

What it does

HOPE Labs opens the tools below, in three categories, and every one of them is a page on a login node.

Folding is its own category rather than more Design because nothing is designed there: a sequence goes in and a structure comes out, which is what somebody who opens the launcher with a sequence in hand is looking for.

HOPE-MD serves its own page, and HOPE Labs only starts it. The others never had one, so theirs is part of HOPE Labs: see The tools whose page is ours.

Opening one of them by hand takes a terminal, an SSH session, the command that starts it, a second session that forwards its port, and a Duo approval for each session. HOPE Labs signs in once, holds that one connection, and does the rest for whichever tool you pick: it starts the tool on the login node, waits for it to say it is ready, forwards a port to it, and shows it in a tab of its own.

The tools are not changed in any way. Each tab shows the tool's own page, with its own Docs and the bar along its bottom. Nothing of the tools is installed on your computer, and the only thing of HOPE Labs on the cluster is its folder: the checkout the pages of ours are served from, and the tools installed beside it.

The page

  1. HOPE Labs, and under it the account you signed in with and the login node it is on.
  2. Tools, Flows and Results, the three views. Tools is where a session starts.
  3. The tools, each with a dot that is green while it is running. Click a name to open that tool's tab, starting the tool first if it is not up.
  4. The one thing to remember about cost: every tool runs under your own account, and the jobs it submits are charged to you.
  5. The categories, one button for each of the four. Pick one to show only those tools; pick it again, or All, to show every one.
  6. Search the tools matches what you type against each tool's name, what it does and its category.
  7. Docs, in the top right corner, opens these pages in a tab of their own.
  8. A block for each tool: what it does, whether it is running, and what it takes from another tool or leaves for the next one.
  9. Launch starts the tool and opens its tab. Once it is running the button says Open, and Stop appears beside it. The dashed buttons open the tool that usually comes next.
  10. The bar along the bottom: the version, the copyright, who does the work, and links to these pages and to How to cite.

Flows

Flows is the second view, and it is for the other way of working: a target, a tool to design against it and a tool to judge what comes back, drawn once as a graph and queued in one go. A card is a tool, its sockets say what it needs and what it leaves, and a link is allowed only where the two meet, so a target cannot be sent where sequences are wanted. The panel down the left of the canvas lists every card there is, which is the answer to which tools can be put in a flow. A card a flow cannot start yet is still drawn and still says what it would do, and it says on itself that it cannot: a flow holding one is refused before anything is queued rather than failing in a job twenty minutes later.

The view is three stages, one at a time, because they follow one another. The canvas is where a flow is drawn. Launch the flow asks the cluster what the flow would do and shows it as a plan, read on the way to queueing and queueing nothing itself: Queue it, in the bar under the plan, is the only button on that page that commits an allocation. A flow that is running is then drawn as its own cards where they were put, colored by what has become of each, with the folders and job ids beside them. A flow is kept on your own computer rather than on the cluster, so Save and the list beside it are yours alone.

A tool's page and its card queue the same run through the same code: the same job script, the same run folder and the same refusals for the same reasons. So a run started either way is found either way, on the tool's own Runs screen and in Results.

A session, start to finish

  1. Start HOPE Labs on your computer and sign in to Grace with your NetID, your password and one Duo approval. The page opens in your browser by itself.
  2. The first time, set HOPE Labs up in a folder of yours on the cluster, and tick the tools to install: see Setting up on a cluster.
  3. Launch a tool. Its tab opens at once and fills in when the tool is ready. The first start of the day can take a minute while the tool's environment loads.
  4. Work in it exactly as you would without HOPE Labs: prepare, submit, follow, read the results.
  5. Hand the result on. Results lists the runs of every tool together, and the button beside a run opens the tool that takes it next, with the run's folder ready to copy.
  6. Sign out when you are done. The pages close and the connection ends; jobs already in the queue carry on.
