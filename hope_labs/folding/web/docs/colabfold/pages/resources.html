Resources and submitting

The card, the walltime, the account, and what the plan box is telling you.

The cards this cluster has

Grace has a100, rtx and t4 nodes in the gpu partition and a40 nodes in gpu-a40, and a job that asks for an a40 in gpu is refused outright, so the partition follows the card you choose. The menu offers the cards the site actually has, largest first, and the default is the largest.

The card is usually what decides whether a folding run finishes. A t4 has 16 GB and an a100 has 40, and both tools grow with the square of the residue count, so the page says plainly when the run looks too large for the card you have chosen.

ColabFold is given 48 GB of host memory and eight cores, which is what the lab's co-folding has always asked for.

Walltime

Four hours is the default. The first five minutes of it are spent importing the tool, which is measured rather than guessed: importing Boltz-2 took five and a half minutes on a compute node here. Grace allows four days on its GPU partitions, and the page refuses a walltime longer than the partition will take.

Account

Left empty, the job is charged to your default account. Fill it in when you have more than one and the run belongs to a particular project.

The plan box

It says what Slurm will be asked for and where the work will happen: the card, the partition, the cores, the memory, the walltime, and whether the alignments will be fetched on the login node before the job is queued. Read it before pressing Submit. It is the only place that tells you, without guessing, what the next few hours of a card will be spent on.

When the tool is not installed here

The page says so across the top, names the folder it looked in, and refuses to queue a run. It still shows you a FASTA record a run would be written, which is worth having: the lab's two clusters do not hold the same tools, and knowing what a run would ask for is useful even where it cannot be asked.

Submit and Dry run

Submit fetches the alignments and queues the job. Dry run writes the run folder, a FASTA record and the job script, fetches nothing and queues nothing. Both leave a folder the Runs screen can read, so a dry run is listed with the rest, marked as one.
