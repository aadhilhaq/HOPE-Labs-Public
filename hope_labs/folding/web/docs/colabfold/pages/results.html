What a run leaves

The folder, the files in it, the numbers beside each structure, and how to take any of it somewhere else.

The run folder

demo_20261005-1830/
  submission.json              what was asked for, and what Slurm was asked
  entities.json                the rows exactly as they were given
  inputs/demo.fasta            what phase one read
  fold/demo/
    demo.a3m                   phase one's alignment
    demo.pickle                the same alignment, as ColabFold keeps it
    demo_unrelaxed_rank_001_alphafold2_multimer_v3_model_3_seed_000.pdb
    demo_scores_rank_001_....json
    demo_predicted_aligned_error_v1.json
    cite.bibtex                the citations for this exact configuration
  job.sbatch                   the job, as it was queued
  slurm_12345678.out           the log
  cache/                       everything the tool wanted to write in your home folder

The alignments are the large part. Phase one leaves several megabytes per protein sequence, and a run with a few chains in it is a few hundred megabytes before a structure is written. That is why the run folder goes in your scratch and why the page refuses to put one in your home folder.

The numbers beside each structure

ColabFold writes a scores file beside each structure. The page shows the mean pLDDT across the chain, and pTM and ipTM where the model produced them. For a complex the confidence column is the ipTM, which is what ColabFold itself ranks a complex by; for a single chain it is the mean pLDDT.

The structures are named rank_001 upwards, best first, and the rank is part of the filename rather than something the page worked out.

ColabFold also writes cite.bibtex into the run, listing the papers for the exact configuration that ran. It is the most reliable citation list for a particular run, and it is offered for download.

pLDDT is per residue confidence and is the one to look at first. pTM says how much of the fold is likely to be right overall, and ipTM says how much the interface between chains is likely to be right, which for a complex is usually the question you came with.

The report

Report (PDF), on the run you have open, writes the run up and opens it in a new tab with the print window ready. It is offered for a run that stopped as well as one that finished, because a run that ran out of walltime with two samples on disk is exactly the one whose numbers you need; the report says in its first lines that the job did not finish and reports what is on disk. It holds, in order: a summary of what was folded and how the best sample scored; the chains, one row each, with their lengths, their modifications, the alignment that served them and their mean pLDDT; the models, best first, with every confidence number ColabFold wrote beside them; the confidence along the chains, as pLDDT per residue in AlphaFold's bands and as the predicted aligned error; the best model drawn in 3Dmol and colored by pLDDT; the alignments phase one fetched, with ColabFold's own coverage plot of them; the methods, written from what this run actually did, with the references for it; and an appendix of the settings as asked and as run, the input the job was given, both phases of the work with the node and the card they used, the versions, and the files.

Along the top of the report is a bar. The tick boxes choose which sections to include, and the options beside them are this page's own: which model the figures are about, how many models the table shows, whether to include the aligned-error map and whether to include the alignments section. Save as PDF opens your browser's print window, which is what writes the file; Copy the methods and references puts the methods paragraph and its numbered references on your clipboard, ready for a manuscript. The zoom control beside them (50 to 200 per cent) is for reading on screen and is kept in your browser: it never reaches the PDF, which always prints black on white at full size.

Every caption states the result from this run's own numbers, so a figure can be read without the text around it. A caption is written by the server as the report is built, never a fixed line of prose, and a caption with nothing to compare says what is missing instead. The sample table of a run that folded one 338-residue chain into four models, for instance, is captioned:

Model 1 ranks first on mean pLDDT, 94.4, ahead of model 3 (94.3), model 2 (94.1) and model 4 (93.6), though model 3 has the higher pTM, 0.82 against 0.81; ColabFold ranked by mean pLDDT because the run is one chain. Higher is better; pLDDT out of 100, pTM from 0 to 1.

What the report does not have yet is a way of adding your own pictures to it. The structure figure in it is drawn by the report itself from the run's own file; the viewer on this screen has no Add to report button, so a view you have turned and colored by hand cannot be put in the report. The report says so where that section would be.

Taking the results somewhere

Two ways, because they answer different questions.

To a folder on the cluster. Give a path, or press Browse and choose a folder, and press Copy the structures, or Copy the whole run. This is much faster than going through this page, and it is where the lab's work belongs. A path inside your home folder is refused, with the reason: home is 10 GB and 10,000 files, and one run is more than both.

To your own computer. Save beside each structure, and Save the best model on my computer, ask your browser where to put the file. In Chrome you get a real folder and filename chooser; in Firefox and Safari the file goes to your downloads folder, because those browsers have no chooser to offer. A structure is a few hundred kilobytes, so this is the right way to take one model and the wrong way to take a whole run.
