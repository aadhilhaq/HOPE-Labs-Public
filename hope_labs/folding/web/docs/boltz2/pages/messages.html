What the messages mean

The refusals on the form, the refusals at Submit, and the lines in a job's log that are worth recognising.

On the form

'J' is not an amino acid

A letter the tool has no residue for, marked where it is in the sequence box. It is refused here because it would not be refused by the tool: the character would become an unknown residue and the structure would come back with a confidence score on it.

take the gaps out

There is a gap character in the sequence, which usually means a row of an alignment was pasted rather than a sequence. A gap is not a residue, and it stops the job rather than being ignored.

%d residues in all, and 5000 is the most this page will queue

What it says. A complex that size wants more than one card, and this page asks for one.

At Submit

the alignments could not be fetched

Phase one failed and nothing was queued. The alignment server rations its answers and queues when it is busy, so trying again later is usually the answer. The sentence after the colon is the server's own.

the alignment fetch gave up after 40 minutes

The server took longer than the page is prepared to hold a login node for. Nothing was queued. Try again, or fold from the sequence alone if you only want a look.

Boltz-2 is not installed on <site>

The page is running somewhere the tool is not. It names the folder it looked in. The form still works and still shows what a run would be told; Submit does not.

In the job's log

STOPPING: there is no usable GPU on this node

The job asked for a card and Slurm gave it one, and then nvidia-smi found nothing, which means the driver and the node disagree rather than that the queue went wrong. The job stops rather than folding on the processor, which would spend the whole booking and finish nothing.

STOPPING: the tool finished and wrote no structure

The job's own check. Both tools can finish having produced nothing and report success, so the script looks for the structures and refuses to call that a completed run. The reason is in the lines above.

Failed to process <path>. Skipping.

In the job's log. Boltz-2 wraps every input in a catch all, prints this and carries on, and if it was the only input it then exits reporting success having produced nothing. That is why the job script looks for the structures afterwards and stops with a message of its own when there are none. The line above this one in the log is the real reason.

Missing MSA's in input and --use_msa_server flag not set.

Boltz-2's own words, in the job's log, for a protein chain whose msa line is absent. The page always writes one, so this means the YAML in the run folder was edited by hand. Add msa: empty to the chain, or point it at an alignment.

Cannot mix custom and auto-generated MSAs in the same input!

Also Boltz-2's own, and also only reachable by editing the YAML: either every protein chain names an alignment or none of them does.
