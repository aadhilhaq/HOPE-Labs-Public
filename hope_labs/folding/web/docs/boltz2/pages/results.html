What a run leaves

The folder, the files in it, the numbers beside each structure, and how to take any of it somewhere else.

The run folder

demo_20261005-1830/
  submission.json              what was asked for, and what Slurm was asked
  entities.json                the rows exactly as they were given
  inputs/demo.yaml             what the job read
  msa/entity_1.csv             phase one's alignment, one per distinct protein sequence
  out/boltz_results_demo/
    predictions/demo/
      demo_model_0.cif         the best structure
      confidence_demo_model_0.json
  job.sbatch                   the job, as it was queued
  slurm_12345678.out           the log
  cache/                       everything the tool wanted to write in your home folder

The alignments are the large part. Phase one leaves several megabytes per protein sequence, and a run with a few chains in it is a few hundred megabytes before a structure is written. That is why the run folder goes in your scratch and why the page refuses to put one in your home folder.

The numbers beside each structure

Boltz-2 writes a confidence file beside each structure. The page shows four of its numbers: the confidence score Boltz-2 ranks by, the complex pLDDT, and pTM and ipTM. The pLDDT is a fraction of one in the file and is shown as a percentage, so that the two folding pages read alike.

The structures are named <name>_model_0 upwards, best first. The page shows them ranked from one, because every other ranking on these pages starts at one.

pLDDT is per residue confidence and is the one to look at first. pTM says how much of the fold is likely to be right overall, and ipTM says how much the interface between chains is likely to be right, which for a complex is usually the question you came with.

The report

Report (PDF), on the run you have open, writes the run up and opens it in a new tab with the print window ready. It is offered for a run that stopped as well as one that finished, because a run that ran out of walltime with two samples on disk is exactly the one whose numbers you need; the report says in its first lines that the job did not finish and reports what is on disk. It holds, in order: a summary of what was folded and how the best sample scored; the chains, one row each, with their lengths, their modifications, the alignment that served them, their chain pTM and their mean pLDDT; the samples, best first, with every confidence number Boltz-2 wrote beside them; the chain-pair ipTM matrix, each chain against each other; the confidence along the chains, as pLDDT per token in AlphaFold's bands and as the predicted aligned error; the best structure drawn in 3Dmol and coloured by pLDDT; the alignments phase one fetched; the methods, written from what this run actually did, with the references for it; and an appendix of the settings as asked and as run, the input the job was given, both phases of the work with the node and the card they used, the versions, and the files.

Along the top of the report is a bar. The tick boxes choose which sections to include, and the options beside them are this page's own: which sample the figures are about, how many samples the table shows, which prediction to report when an old run folder holds two, whether to include the aligned-error map and whether to include the alignments section. Save as PDF opens your browser's print window, which is what writes the file; Copy the methods and references puts the methods paragraph and its numbered references on your clipboard, ready for a manuscript. The zoom control beside them (50 to 200 per cent) is for reading on screen and is kept in your browser: it never reaches the PDF, which always prints black on white at full size.

Every caption states the result from this run's own numbers, so a figure can be read without the text around it. A caption is written by the server as the report is built, never a fixed line of prose, and a caption with nothing to compare says what is missing instead. The sample table of a run that folded a 95-residue protein dimer with a 20-base DNA strand into three samples, for instance, is captioned:

Sample 1 has the best confidence score, 0.887, ahead of samples 2 (0.883) and 3 (0.878), though sample 2 has the highest ipTM, 0.938 against 0.931; all three put the interface PDE below 0.41 Å. Higher is better for every column except the two PDEs, where lower is better.

What the report does not have yet is a way of adding your own pictures to it. The structure figure in it is drawn by the report itself from the run's own file; the viewer on this screen has no Add to report button, so a view you have turned and coloured by hand cannot be put in the report. The report says so where that section would be.

Taking the results somewhere

Two ways, because they answer different questions.

To a folder on the cluster. Give a path and press Copy the structures, or Copy the whole run. This is much faster than going through this page, and it is where the lab's work belongs. A path inside your home folder is refused, with the reason: home is 10 GB and 10,000 files, and one run is more than both.

To your own computer. The save button beside each structure, and Save the best model, ask your browser where to put the file. In Chrome you get a real folder and filename chooser; in Firefox and Safari the file goes to your downloads folder, because those browsers have no chooser to offer. A structure is a few hundred kilobytes, so this is the right way to take one model and the wrong way to take a whole run.
