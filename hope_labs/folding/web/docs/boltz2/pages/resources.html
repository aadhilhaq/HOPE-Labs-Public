Resources and submitting

The GPU, the time limit, the account, and what the run plan is telling you.

The GPU

Grace has a100, rtx and t4 nodes in the gpu partition and a40 nodes in gpu-a40, and a job that asks for an a40 in gpu is refused outright, so the partition follows the card you choose. The GPU menu offers the cards the site actually has, largest first. Left on Auto the job asks for the largest, which is the right choice for almost every run; the others are there to ask for a smaller card on purpose, to get through the queue sooner.

The card is usually what decides whether a folding run finishes. A t4 has 16 GB and an a100 has 40, and both tools grow with the square of the residue count, so the page says plainly when the run looks too large for the card you have chosen.

Boltz-2 holds a 2.2 GB checkpoint and the pair representation of the whole complex at once, so it is given 64 GB of host memory and eight cores.

Time limit

Four hours is the default. The first five minutes of it are spent importing the tool, which is measured rather than guessed: importing Boltz-2 took five and a half minutes on a compute node here. Grace allows four days on its GPU partitions, and the page refuses a time limit longer than the partition will take.

The arrows move it by the half hour. Estimate fills in a generous allowance worked out from what is on the form, which is the only thing here that knows how much there is to fold. A job that ends early is charged for what it used; one that runs out has to be queued again from the beginning, so the allowance is rounded up.

Account

Left empty, the job is charged to your default account. Fill it in when you have more than one and the run belongs to a particular project.

The run plan

Once there is something to fold, the run plan appears in the column on the right, directly above Submit, because that is the moment it is wanted. It is the steps a run will take, one line each, with where each happens and roughly how long it takes:

1  Alignments   fetched now, on this login node   about 1 min
2  Folding      1 structure on one A100            about 7 min
Results in My scratch/...

The times are rough, from the lab's own runs on this cluster, and they are how long each step runs once it starts, not the wait in the queue, which nobody can know. With Alignments set to Sequence only there is no first step. Show the job under the plan opens a YAML file exactly as the job will read it, the command that reads it, and what Slurm is asked for: the card, the partition, the cores, the memory and the time limit.

When the tool is not installed here

The page says so across the top, names the folder it looked in, and refuses to queue a run. The form is still checked, row by row, but Submit and Show the job wait for a cluster that has the tool: the lab's two clusters do not hold the same tools.

Submit and Dry run

Submit fetches the alignments and queues the job. Dry run writes the run folder, a YAML file and the job script, fetches nothing and queues nothing. Both leave a folder the Runs screen can read, so a dry run is listed with the rest, marked as one.
