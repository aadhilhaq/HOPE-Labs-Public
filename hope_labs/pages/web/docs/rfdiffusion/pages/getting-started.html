Getting started

Open the page, give it a four-character PDB id, name a few residues, and press Dry run. That writes everything a real run writes and queues nothing, which is the cheapest way to see what you are about to ask for.

Opening the page

From HOPE Labs: sign in, go to Tools, find RFdiffusion and press Launch. The launcher starts the page on a login node, forwards the port to your own computer and opens it in a tab. Nothing needs installing on your machine.

From a terminal on the cluster, if you would rather, in the HOPE Labs folder:

cd <folder>/HOPE-labs
PYTHONPATH=. ../envs/hopelabs/bin/python3 \
    -m hope_labs.pages.serve rfdiffusion --port 0

It prints the address to tunnel to and then a line beginning open with a URL in it. That URL carries a token, and nothing but this documentation answers without it, so the page is yours even though the login node is shared with everybody else logged into it.

A login node, not a compute node. The page itself does nothing heavy: it reads a structure, talks to the queue and waits. The design runs in a job on a GPU node, which is what the page queues.

Where runs go

By default a run goes in $SCRATCH/rfdiffusion_runs, in your own scratch, which is also where a flow puts its RFdiffusion runs. So the Runs screen shows both, and a run started one way can be read the other way.

Your home folder on Grace holds 10 GB and 10 000 files, and one run writes more files than that between its caches and its backbones. The page refuses a run folder inside home for that reason. Put runs in scratch.

A first run

  1. In Target, type a four-character RCSB id and press Fetch. The page fetches the entry, reads it, and shows one chip per chain with the residue numbers that chain actually uses.
  2. Leave every chain selected, or click a chip to drop one. Most targets are given as the chains a binder should bind.
  3. In Where the binder should bind, type the residues to aim at, in the numbering the chips show: 54,56,66-70 for one chain, or A54,B12-16 across chains. The box below fills in with the contig map and the hotspot list the job will be given.
  4. In the rail on the right, set the binder length and how many backbones to generate. The defaults are ten backbones of 70 to 100 residues, with eight sequences designed for each.
  5. Press Dry run. The run folder is written, the structure is copied into it, the plan and the job script are written, and nothing is queued. Read the job script if you like: it is the one a real submission would send.
  6. When it looks right, press Submit. The page moves to the Runs screen with the new run open.

How long it takes

A diffusion is minutes per backbone on an A100, and longer the larger the target and the longer the binder. Ten backbones of a hundred residues onto a small receptor is comfortably inside the default twelve hours; a hundred backbones onto a large one is not. The Resources group is where to lengthen the walltime, and Walltime and starting again explains why running out is worse here than it is for some tools.
