The binder

How long the binder should be, how many to make, and the two knobs that change what the diffusion does rather than how it is run.

The length range

Shortest and Longest are a range, and a length is sampled inside it for every backbone. The default is 70 to 100 residues, which is a small folded miniprotein: long enough to have a hydrophobic core and a face to bind with, short enough to be synthesised and expressed.

A wide range gives designs that are hard to compare with each other, and the page says so when the range is wider than about sixty residues. If you want one length, set both boxes to it.

Below about thirty residues a designed chain will not fold on its own. It can still be a useful peptide, and the docking downstream takes nothing longer than thirty, but it is a different kind of design from a miniprotein and RFdiffusion was not trained for it.

Backbones and sequences

Backbones to generate is the whole size of the run. Each one is a separate diffusion from a different starting noise, so ten backbones are ten independent attempts at the same site, not ten views of one answer. Minutes each, and the run is this many.

Sequences per backbone is how many sequences ProteinMPNN proposes for each design. It runs with the target held fixed and only the diffused chain free, so what it designs is the binder and nothing else. The best of them, by ProteinMPNN's own score, is the one kept and written into designs.json; the rest stay in the run folder under proteinmpnn/ if you want to look at them.

Eight is the default and is usually plenty. The two numbers multiply, so a hundred backbones with eight sequences each is eight hundred sequence designs, and the page warns when the product gets large enough to matter to the walltime.

The diffusion's own knobs

These sit behind More settings, because the defaults are the ones RFdiffusion's own binder-design example uses and most runs should leave them alone.

SettingWhat it does
Noise scaleHow much noise the denoiser is given, on both the positions and the frames. The example lowers it to 0 for binder design, which is what makes the backbones worth giving a sequence to. Raising it asks for more varied designs, and fewer of them will fold.
Diffusion stepsHow many denoising steps each design takes. Fifty is the default. Fewer is faster and rougher, and fifteen is the least the box takes: RFdiffusion asserts on anything lower while it builds its schedule, so a smaller number spends a card and writes nothing.
CheckpointWhich model weights to use. Empty takes the binder-design default, which is the right answer unless you have a reason. The complex checkpoints are the two the install ships.

What the form does not offer

The card this form is built from also carries a Relax each design before scoring tick. The page leaves it out, and so does a flow, because nothing reads it: relaxing a design before ProteinMPNN scores it needs the interface script from dl_binder_design, and that needs a PyRosetta licence this install has not got. Rather than show a control that changes nothing, the page does not show it.

What the run does instead is call ProteinMPNN's own script directly on the diffused backbone. That needs no PyRosetta and is what has been proven here end to end.
