Resources and submitting

One GPU job does the whole run: the diffusion and the sequence design together, in RFdiffusion's own environment. What follows is what that job asks Slurm for, and why.

The card and the partition

Card is which GPU to ask for. auto means an A100, which is what both halves of the run are comfortable on.

The partition follows the card. On Grace the A100s, the T4s and the RTX cards are in gpu and the A40s are a partition of their own, gpu-a40, so a job asking for an A40 in gpu is refused outright rather than queued. The page works the partition out from the card and shows it in the What Slurm will be asked for box, so you can see what is about to be asked. Naming a partition yourself in More settings overrides that, which is there for a reservation.

Walltime and starting again

Twelve hours is the default and four days is the most the gpu partition allows. Write it as 12:00:00, or 2-00:00:00 for two days.

There is no checkpoint. A job that runs out of walltime loses the run. The backbones already written stay on disk and can be read, but designs.json is written at the very end, and Queue again on the Runs screen starts the same job script from the beginning rather than carrying on. So it is worth asking for longer than you think you need: an idle hour on a card costs the allocation far less than a lost twelve.

Cores, memory and the caches

The job takes eight cores and 48 GB of host memory, and neither is a choice on the form. They are what the two halves of the run need and nothing is gained by asking for more; the box shows them so a run's provenance is complete.

Everything the job writes for itself goes inside the run folder. The job script points XDG_CACHE_HOME, MPLCONFIGDIR, CUDA_CACHE_PATH, TMPDIR, HF_HOME and TORCH_HOME at cache/ under the run, so nothing reaches your home folder, which on Grace would fill up and start failing other things. The caches are safe to delete once a run is finished.

The account

Account to charge is empty by default, which charges your own default allocation. Fill it in only if you have been told to put this work on a particular account. The page does not check that you are a member of it; Slurm does, at submission, and says so.

Submit and Dry run

Submit writes the run folder, copies the structure into it, writes the plan and the job script, and queues the job. Dry run does all of that except the last step.

A dry run is not a simulation of a submission. It is the submission, with sbatch taken out: the same target fetch, the same checks, the same plan, the same script. If a dry run is refused, a real one would have been refused for the same reason, and the reason is the one you see. It is the right first move on any target you have not used before.

Submit stays off while the Before this can be queued box has anything in it. Those sentences are the same ones a flow holding this card would be refused with, so a form the page will take is a flow the cluster will take.
