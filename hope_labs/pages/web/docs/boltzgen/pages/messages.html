What the messages mean

The sentences the page and the job can produce, what each one is telling you, and what to do about it.

Before anything is queued

What it saysWhat to do
the target needs hotspots: the residues a binder should touchName a few residues. A run is not queued without them.
the target has no residue A218The number is not in the chain. The chips under the target show the range each chain actually uses, and plenty of entries do not start at 1.
the target has no chain CA chain was dropped, or the entry does not have it.
BoltzGen needs what to designChoose a protocol. It is the whole of what the model is being asked and there is no sensible default for a target the page has not seen.
the structure has to be a .pdb fileThe hotspot conversion reads the target by PDB columns, so an mmCIF would be copied in and then found empty.
no amino-acid chain was found in that fileThe file has no ATOM records the conversion can read.
the RCSB would not give 9ZZZThe id does not exist, or the RCSB is not answering. The message carries what it said.
home is 10 GB and 10 000 files on GracePut the run folder in your scratch.
a walltime Slurm takes: 12:00:00, or 2-00:00:00 for two daysSlurm's own forms only. The gpu partition allows four days at most.

When the run will not queue

What it saysWhat it means
BoltzGen's weights are not in /scratch/.../boltzgen_cacheThe 10 GB weight cache is missing, and a compute node cannot fetch it, so nothing is queued at all. It is fetched on a login node; this is not something the form can fix.
sbatch refused the jobSlurm's own complaint, passed through. The usual causes are an account you are not a member of, a partition that has no such card, or a walltime over the partition's limit.
there is no BoltzGen on the clusterFrom the launcher, not the page: the install is not where it is expected. Check the path on the Tools screen.

In the log

What it saysWhat it means
hotspots: chain A 54,56,66 to positions 37,39,49 (the chain is numbered 18 to 290) The conversion, written down. Read it: these are the residues the run will actually aim at.
hotspots: 7 residue(s) confirmed in the specBoltzGen wrote the specification out as a structure, the marks were read back, and they are the positions that were asked for. Past this point the hotspots are proved.
the hotspots did not survive conversionThe marks read back are not the ones asked for, so the run stops before anything expensive. Nothing has been queued beyond the check. Send the run folder on: this should not happen and the specification in it is the evidence.
these hotspots are not residues of the target, so nothing was runA hotspot named a residue the structure has not got: one in a gap in the chain, one off the end of it, or one on a chain that is not among those kept. Each is named, with where it falls, and the run stops before anything expensive. RFdiffusion and RFdiffusion3 refuse the same thing in the same words.
these hotspots have an insertion code, which this tool cannot be aimed at, so nothing was runA hotspot was written 60A or H60A. The conversion to positions reads a chain, a number and at most a range, so the code is lost and the run would aim at residue 60, which a structure numbered this way has as well. RFdiffusion refuses it in these same words; RFdiffusion3 is the one of the three that keeps a code on its residue, so use that page when 60A is the site.
none of the hotspots given are in the targetEvery residue named is absent, so there is nothing to aim at and the run stops.
BoltzGen left no metrics CSVThe run finished the generation but the analysis step produced no table, so there is no ranking to hand on. Usually the analysis step running out of card memory, which is the one to suspect at a high design count.
pdl1_design_3: no chain in the structure carries the designed sequenceOne design could not be split into binder and target by sequence, so it was dropped rather than handed on the wrong way round. One or two in a run is not a problem.
pdl1_design_5: no structure among the ranked designsThe design is in the metrics table but BoltzGen wrote no structure for it in either ranked folder. It is dropped.
wrote designs.json: 9 design(s)The run finished. Nine designs came through with both a structure and a sequence.
no design came through with both a structure and a sequenceThe run finished and produced nothing usable. The lines above it say which designs were dropped and why.
CUDA out of memoryThe card ran out. Fewer designs, a shorter binder, or an A100 rather than an A40.

Slurm states on the Runs screen

StateWhat it means
PENDINGWaiting for a card. The reason beside it is Slurm's, and Resources or Priority both mean wait.
RUNNINGOn a node. The log is a better guide than the tiles for most of a BoltzGen run, because its output arrives at the end.
COMPLETEDThe job exited cleanly. Check the designs tile: a run can complete having dropped every design.
TIMEOUTOut of walltime. There is no checkpoint, so the run is lost; ask for longer or for fewer designs.
OUT_OF_MEMORYThe host ran out, not the card. Unusual at 64 GB and worth reporting.
DRY RUNNot a Slurm state. The run folder, the specification and the job script were written and nothing was queued.
