Resources and submitting

One GPU job does the whole run: generation, inverse folding, re-folding and the analysis that ranks what came out. What follows is what that job asks Slurm for, and why.

The card and the partition

Card is which GPU to ask for, and only the two large ones are offered. BoltzGen wants 40 GB or more: upstream reports it running out of memory on a modest target on a 16 GB card, and again in its analysis step. The T4s and the RTX cards on Grace are therefore not choices here.

The partition follows the card. On Grace the A100s are in gpu and the A40s are a partition of their own, gpu-a40, so a job asking for an A40 in gpu is refused outright rather than queued. The page works the partition out from the card and shows it in the What Slurm will be asked for box. Naming a partition yourself in More settings overrides that, which is there for a reservation.

An A40 has 48 GB and will hold a run, but the analysis step is the one that has been seen to run out, so the page says so when you choose one.

Walltime and starting again

Twelve hours is the default and four days is the most the gpu partition allows. Write it as 12:00:00, or 2-00:00:00 for two days.

There is no checkpoint. A job that runs out of walltime loses the run. The designs already written stay on disk, but the ranking and designs.json come from the analysis step at the end, and Queue again on the Runs screen starts the same job script from the beginning rather than carrying on.

Cores, memory and the caches

The job takes eight cores and 64 GB of host memory, and neither is a choice on the form. The larger allowance here than for the lab's other diffusion tool is the analysis step; the box shows them so a run's provenance is complete.

Everything the job writes for itself goes inside the run folder: XDG_CACHE_HOME, MPLCONFIGDIR, CUDA_CACHE_PATH, TMPDIR and TORCH_HOME all point at cache/ under the run, so nothing reaches your home folder. HF_HOME is the exception: it points at the group's weight cache, because the weights are 10 GB and every run reads the one copy. The job also runs with Hugging Face's offline flag set, so it cannot try to fetch anything from a node that has no internet.

The account

Account to charge is empty by default, which charges your own default allocation. The page does not check that you are a member of an account you name; Slurm does, at submission, and says so.

Submit and Dry run

Submit writes the run folder, copies the structure into it, writes the specification and the job script, and queues the job. Dry run does all of that except the last step.

A dry run is the submission with sbatch taken out: the same target fetch, the same hotspot conversion, the same checks, the same script. If a dry run is refused, a real one would have been refused for the same reason. It is the right first move on any target you have not used before, and on this tool it is also how to read the converted hotspots in the specification file itself.

Submit stays off while the Before this can be queued box has anything in it. Those sentences are the same ones a flow holding this card would be refused with.
