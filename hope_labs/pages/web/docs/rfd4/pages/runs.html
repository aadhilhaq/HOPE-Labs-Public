The Runs screen

Where a queued run appears, what its states mean, and where its folder is.

Where runs go

Each run is a folder under $SCRATCH/rfd4_runs, named for when it was queued. A run started from this page and one started from a card on the canvas go to the same place, so either is listed on the Runs screen whichever way it was started.

States

The screen reads Slurm rather than guessing from files: queued, running, finished, failed. A run whose job has left the queue without writing designs.json is shown as failed even if the structures are there, because the record the next card reads is what makes a run usable.

While a run is going, the screen counts the designs it has written. They appear one folder at a time under rfd4/inference_samples, so the count moves as the run works rather than all at once at the end.

Queue again

Queue again submits the same job script afresh. There is no checkpoint to carry on from, so this is a restart rather than a resume; the previous run's folder is left alone.

Cleaning up

A finished run tidies itself, so what is left is the structures, the spec, the plan, the log and the record. Clean up does the same thing on demand, for a run that finished before that was the rule or one you want reduced now.

The run folders are yours to delete. The image and the weights are shared and are not in them, so removing a run removes only that run.
