Getting started

Open HOPE-MD from HOPE Labs with one Duo approval, then make a first run. The page runs on a login node; everything it computes is a Slurm job.

What you need

A Grace account at Texas A&M HPRC: your NetID, its password and Duo. Jobs charge your default HPRC allocation, which myproject shows on a login node. Your account also needs the access below; id -Gn on a login node lists your groups.

On your computer: HOPE Labs' launcher, and a browser.

Opening it from HOPE Labs

HOPE Labs opens HOPE-MD in a tab of its own: pick HOPE-MD and press Launch. It starts the HOPE-MD that Set up installed in your HOPE Labs folder, on the login node it is signed in to, over its one connection, so the one Duo approval you gave HOPE Labs covers HOPE-MD too. The page in the tab is the same page, with its own Docs.

A run handed on from HOPE Labs' Results, a docking run to simulate for instance, arrives as a folder path under HOPE Labs' bar with a Copy path button: paste it into the path box of the matching source, such as Complex file.

The runs folder

Every run is a folder in the runs folder the page has open. The header says which one it is. You never have to name it: it is your own scratch, /scratch/user/<NetID>/hopemd_runs, made the first time.

The page can open another at any time: Another folder on the Runs screen opens the browser on the places this server may read (My scratch, your home and the others that exist), and Open this folder takes the folder shown for the rest of the session. A folder you cannot write to opens too, marked read-only in the header: its runs open and read as any other, and a report is shown even where it cannot be saved. In a folder others share, a report, a video or an MM-GBSA rerun is written beside the run, under the account that asked for it.

Submit writes into the folder that is open. After reading another folder's runs, browse back to your own (My scratch, then hopemd_runs) before you submit.

What runs where

WhereWhat
Your computerThe launcher and the browser. Nothing of HOPE-MD is installed there beyond the launcher.
A login nodeThe page's server. It serves the page, reads the structures you load, writes the input files and job scripts, submits them, and reads the results back. It also reaches the RCSB, OPM, UniProt and EBI for the imports and the transmembrane search.
The compute nodesEvery computation, as a Slurm job under your account: Prepare, the ligand's parameters, the build, equilibration, production, the analysis, MM-GBSA and tidy, and the media (the videos, the snapshots, a dense window of the trajectory).

No stage of a run computes on a login node. The engines are never installed: each job loads its engine from the cluster's modules, so the versions are the cluster's.

A first run

  1. Choose a structure. On the Structure card press PDB code, type 1BHL and press Fetch. The two chains appear in the viewer, and the checks list what the entry holds: each chain with its resolved and missing residues, the hetero groups, the waters, and that it is not prepared yet. Chain A is the receptor and chain B the partner.
  2. Prepare. Press Prepare. The job goes to the short partition and the note under the button follows it from queued to done, a minute or so. The checks then say what Prepare did: 1BHL's cacodylated cysteines mapped to cysteine, the loops modeled, the chain breaks left open, PROPKA's protonation states, the minimization, and the clashes before and after.
  3. Protocol. The page opens on Standard (100 ns × 3). Pick Quick check (10 ns × 1). The walltime follows the estimate.
  4. Submit. The run folder is written as hopemd_runs/1BHL_amber in your scratch, the graph is queued (build, equilibration, production, then the analysis and MM-GBSA, then tidy) and the page moves to Runs.
  5. Runs. A row for each stage shows its state, and a click on one shows its log. When the analysis job has run, the tiles and the trajectory appear; the MM-GBSA table fills when its own job ends. Report writes the run's report, and Video queues its two videos.

A Quick check takes one to three hours from Submit, most of it in the queue. The other sources work the same way: Sources says what each one takes.

Without the launcher

Log in with the port forwarded, so the tunnel ends on the login node the server runs on, and start the server in that same session:

ssh -L 8098:127.0.0.1:8098 <NetID>@grace.hprc.tamu.edu       # on your computer
cd <HOPE Labs folder>/HOPE-MD/MD && . ./activate.sh
python3 -m hopemd.server --port 8098 --runs $SCRATCH/hopemd_runs

It prints a line beginning open with the page's address and its token: open that address in your browser. sbatch ready in its first line means Submit queues jobs; DRY RUN (no sbatch) means it writes run folders and queues nothing. If another user holds port 8098 on that node, the server stops with Address already in use: choose another number in both commands. Ctrl-C stops the server.

ACES, Texas A&M's accelerator cluster, signs in with a certificate from its portal rather than a password, and has no NAMD 3, so the page leaves NAMD out there. ACES.md in the repository covers installing there and ACES (TAMU) in the launcher.
