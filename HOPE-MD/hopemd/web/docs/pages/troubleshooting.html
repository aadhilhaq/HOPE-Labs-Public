When something goes wrong

HOPE-MD says what it found in a sentence: under Load, under Prepare, in red under a field, under Submit, or in a job's log. Here are those sentences, what each means, and what to do. Words in italics stand for what the sentence names.

Opening the page

What you seeWhat it means, and what to do
The launcher says Could not connect: user@host was not acceptedGrace refused the sign in: check the NetID, the password and the Duo approval, and connect again.
Could not connect: there is no directory folder on the clusterThe tool directory is wrong. Set up installs it in <HOPE Labs folder>/HOPE-MD/MD.
Could not connect: HOPE-MD was not found at folderThe folder exists but holds no HOPE-MD. Point the tool directory at the shared install, or at the MD folder of an install of your own.
Could not connect: permission denied on the far endUsually a folder your account cannot read, such as an install in a folder of another account.
Could not connect: the Python on the cluster is too old, or the cluster ran this with a Python older than 3.10The install's environment did not load. The shared install finds its own through activate.sh; an install of your own needs its environment beside the checkout, as install.sh makes it.
Could not connect: the port the server was asked for is takenLeave the port box on auto.
Could not connect: the server did not report a URL within 90s, or the server stopped before it printed a URLA slow login node, or a server that stopped: its own last lines follow in the launcher's log. Connect again; if it happens again, send those lines.
The browser shows missing or wrong token; use the URL the server printedThe address was typed or kept without its token, or the page was started again since. Use Open in browser in the launcher, or the address the server printed.
The header says DRY RUNThis server cannot queue anything: it found no Slurm where it runs, or it was started that way (the launcher's This computer). Submit writes the run folder and queues nothing.
A page started by hand stops with Address already in useAnother user holds that port on the login node: choose another number, in the tunnel too.

Loading a structure

The browser stays open with the reason under it, and nothing is loaded.

The note saysWhat it means, and what to do
receptor file not found:, ligand file not found:, poseviewer file not found: or file not found: pathNo file at that path, as the server sees it on the cluster. Choose it in the browser.
no protein or nucleic-acid chain was read from the file: there is nothing in it to simulateThe file holds no chain HOPE-MD can build: check it is a structure with its coordinates, and the receptor's.
chain X is not in the receptor file, which has chains list The chains field names a chain the file has not. Name its chains, or empty the field to keep them all.
the receptor file has modified nucleotides, or modified amino acids whose charge is not their parent's (the same for the partner file)No force field here has parameters for them: give the structure without the modifications. See Modified residues.
the ligand file contains a metalThe ligand force fields here have no parameters for a metal complex, so HOPE-MD does not simulate it.
the first molecule of file could not be readRDKit could not read the small molecule: check its bond orders and charges, or give it as SDF.
'x' is not a PDB idA PDB id is four characters with a digit first, such as 4CMM.
rcsb import failed: reasonThe RCSB did not send the entry: the id does not exist, the assembly is not one it has, or the RCSB could not be reached. Check the id and the assembly, or try asu.
no AlphaFold model in result, or result has no model kNot an AlphaFold result as AlphaFold writes one, or the model asked for is not in it: the sentence names the models it holds, and the number to give for each.
n pose(s) found under folder, so there is no pose k, or file has n structures: no pose kThe pose asked for is past the last one: lower pose.

A bound ligand refused

Choosing a ligand bound in the structure imports the structure again with it; when it cannot be typed, the note says why and the choice goes back to what it was.

The note saysWhat it means
ligand is covalently bound to residueA covalent ligand is part of the polymer, not a separate molecule.
ligand is bonded to residueIt is one residue of a ligand spread over several, which one component of the dictionary cannot type.
ligand contains a metalNo ligand force field here has parameters for a metal complex.
ligand has n of the m heavy atoms the CCD definesAtoms are missing: model them first.
ligand has n heavy atoms where the CCD defines m, or the bonds ligand's coordinates make are not those the CCD definesIt is not the component its name says.
the CCD definition of code could not be fetched from the RCSBThe ligand's bond orders come from it: try again when the RCSB answers.
a bound ligand is typed with RDKit, which this server's Python does not have The page is running without the lab's environment: start it from the shared install, whose activate.sh provides it.

A field in red

A setting that cannot work turns its field red with the sentence under it, the step's number turns red, and Submit stays off with every sentence listed under it, beginning Submit is off:.

The ligand

The sentence beginsWhat to do
The ligand file has no hydrogens.Give the ligand as SDF or MOL2 with its bond orders and formal charges, and its hydrogens are added as drawn; a PDB ligand needs them in the file.
The ligand's net charge was not detected; set it.Type the net charge: a PDB ligand carries none.
The ligand file's formal charges sum to qThe file decides the charge, since HOPE-MD runs the molecule the file draws: to run another, load a file protonated for that charge.
Confirm the net charge (q) before chargingCheck it, then tick charge is right: AM1-BCC with the wrong total runs to completion and is wrong in every frame.
A small molecule needs parametersChoose GAFF2 + AM1-BCC under ligand parameters.

Submitting

What you seeWhat it means, and what to do
Load a structure to enable Submit.Nothing is loaded in this session: press the structure. After Copy to Setup, choose the structure again.
name exists and was submitted; pick another name.A run of that name is in the runs folder: name this one differently.
The imported structure is no longer hereIts staging folder was cleared and no run holds it: load it again.
This run cannot fit in spaceYour quota cannot take it: tidy or delete finished runs, or open a runs folder in another space. See The quota.
A question ending Submit with OPLS4 all the same?OPLS4 needs the OPLS license, which the academic Desmond license lacks: press Cancel and choose OPLS_2005, unless you know the license is there.
In Submit's output: stage: sbatch refused: Slurm's wordsSlurm did not take that job, and the rest of the graph was not queued: its words say why. Put it right, then use Start again on the Runs screen.

For one run per pose, each refused selection is reported in the box with its reason, and the others go. A small molecule's pose is refused with net charge q in this pose's file, not the confirmed q: load that pose and confirm its charge.

Surfaces in the viewer

The surfaces the Setup and Runs viewers draw are computed by MSMS on the server, from the file the viewer shows: the structure on Setup, the frame shown on Runs. A quiet note in the viewer's top right corner says when what you see is something else.

The note saysWhat it means, and what to do
Computing the surface with MSMSThe server is computing it, which takes a second or two; the surface appears when it is done. Each structure, and each frame, is computed once and kept in the run folder, in a hidden .surfaces folder that can be deleted at any time.
Surface drawn by the viewer: reasonMSMS gave no surface, so the viewer drew its own, and the reason says why. MSMS is not installed here: the server found neither the ADCP 1.1 suite, whose MSMS library (mslib) it runs, nor an msms program; it looks for the suite where $ADCPSUITE_HOME points, then in the group folder's tools/docking/adcpsuite, and for a program where $MSMS_EXE points or on the PATH. n atoms is more than this server triangulates, or MSMS took longer than 30 s: the structure is too large to surface on a login node. A figure of the viewer's own surface cites the viewer alone.

In a job's log

The log saysWhat it means, and what to do
Prime MM-GBSA: fewer than the 8 Prime (PSP_PLOP) license tokens it needs were freeThe shared pool stayed busy for the whole two-hour wait. Run it again later with MM-GBSA…: the rest of the run is not held back by it.
A license error at Desmond's buildYour account is not on the Desmond users list (the desmond group), or the run asked for OPLS4: see Desmond.
segment s stopped at multisim's walltime checkpointA Desmond segment reached its walltime and checkpointed: Start again it to continue.
some parameters are guessed (ATTN)parmchk2 guessed some of the small molecule's parameters: the log names the file to read. The run goes on.
pdb2pqr not found or pdb2pqr failed in the buildThe receptor got the build's default protonation states, not PROPKA's at your pH. The line says which were used.
Prepare stopped: reasonSee Prepare.
a disulfide joins the receptor and the partner that the run was set up without, or the run bonds topology residues p and q, but in the build's files no disulfide joins themThe build found a disulfide across the split that the run does not bond, or the run bonds residues the files no longer pair. Import the structure again, so the import measures the bonds on the files the build reads. See A disulfide across the split.
MM-GBSA is not run: the receptor and the partner are covalently linkedAs it says: a disulfide joins the two sides. See When the two sides are bonded.
A module load errorYour account cannot load that module; for Amber, the amber group is missing. The module audit shows which lines load for you.

The module audit tries every module load line the jobs run and writes what it found to a file in the folder you run it from; a line marked CANNOT LOAD is one your account cannot load:

cd $SCRATCH && bash <HOPE Labs folder>/HOPE-MD/MD/scripts/audit.sh

Reporting a problem

Give the run folder's path: it holds the spec, the job scripts, the Slurm job ids and a log for every job, which is almost always enough. For a problem opening the page, tick Show technical details in the launcher and copy what is under What is happening. Open an issue on the HOPE-MD repository, or write to Aadhil Haq at aadhil.haq@tamu.edu. Cluster access, quotas and licenses are HPRC's: help@hprc.tamu.edu.
