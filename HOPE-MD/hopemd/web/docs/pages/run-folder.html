The run folder

Each run is one folder in the runs folder, named after the run. It holds everything the page wrote and every job's log, and each of its jobs can be run again by hand.

What it holds

<runs folder>/<run>/
  spec.json      the run as submitted: its record, and the one file to edit by hand
  README.txt     the settings, and what was derived at submit
  input/         the structure as imported, or as Prepare split it
  build/         the engine's topology and the files that built it
  md/            equilibration and production inputs
  r1/ r2/ ...    one folder per replicate: trajectory parts and restart points
  analysis/      cpptraj and MM-GBSA results, the viewer's trajectory, summary.json
  export/        the videos, the snapshots and report.html when it has been written by hand
  report/        the views added from the viewer, and the words written under them
  jobs/          job scripts, graph.json, ids.json, timing.json, staging.json, software.txt, submit.sh
  logs/          one Slurm log per job
  archive/       tidy_<stamp>.tar.gz, once tidy has packed the small files

README.txt names the module line the run's jobs loaded, and jobs/software.txt what each job's engine then reported its own version to be, which is what lets a reference be checked against what ran. jobs/graph.json is the job graph, each job with what it waits for, and jobs/ids.json the Slurm job ids the Runs screen follows, with those a resubmission replaced.

Working without the page

Every job script runs from its run folder on its own, so a run can be driven from a terminal on a login node, from the checkout with its environment:

cd <HOPE Labs folder>/HOPE-MD/MD && . ./activate.sh
bash <run>/jobs/submit.sh                         # queue the run's job graph again
(cd <run> && sbatch jobs/40_analysis.sbatch)      # one stage
python3 -m hopemd.export.report <run>             # write <run>/export/report.html, on its own
python3 -m hopemd.export.snapshots <run> 1        # queue the first and last frames of replicate 1
python3 -m hopemd.export.portfolio <runs folder> --out $SCRATCH/runs.pdf
python3 -m hopemd.timing <run>                    # record a finished run's timings by hand

jobs/submit.sh keeps the job ids it gets in jobs/ids.txt, which the page does not read: the Runs screen follows the ids in jobs/ids.json, which the page writes. To queue a stage again and keep the page following it, use Start again on the Runs screen.

A run resumed by an older HOPE-MD kept the frames a stopped part wrote past its restart point twice, in an Amber, OpenMM or NAMD trajectory. Cut them, then resubmit the analysis and MM-GBSA; on a tidied OpenMM run, Undo tidy first, since the cut reads its parts' logs: 
python3 -m hopemd.analysis.parts join <run>
