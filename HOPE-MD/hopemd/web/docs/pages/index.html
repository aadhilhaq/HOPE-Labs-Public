HOPE-MD

Molecular dynamics of a complex on Texas A&M's Grace cluster, from one page in your browser: import the structure, prepare it, choose an engine and a protocol, submit, and read the run back as plots, a trajectory, MM-GBSA binding energies, a report and videos.

What it does

You give it a structure: a docked pose, a PDB entry, an AlphaFold model or a complex file. HOPE-MD prepares it, writes every input file and job script the engine needs, submits the whole job graph to Slurm, follows it, and reads the results back. No input file or job script is written by hand.

A run is one spec, spec.json in the run's folder. Five engines, Amber, OpenMM, GROMACS, NAMD and Desmond, each render the same spec into their own inputs, so the same complex moves to another engine by changing one field.

Every setting is chosen, detected or derived. You choose the ones in the form. What the import finds (the chains, the partner's class, the waters, a model's confidence) is detected and shown, never typed. What follows from the rest (the box, the atoms, the frames, the run time) is derived and shown in the panel under the form. A value that cannot work turns its field red with a sentence in the field's own units, and Submit stays off while anything is red.

HOPE-MD does not dock: it simulates the pose it is given, and says so when the partner it is given does not touch the receptor. The engines and tools it drives belong to their authors, and each job loads them from the cluster's own modules.

The path through a run

  1. Choose a structure. Press Choose a structure on the first card and pick the file, folder or PDB code; the viewer and the checks show what was found. See Sources.
  2. Prepare it, for an RCSB entry, a complex file or an AlphaFold model: set what Clean keeps and press Prepare to see the result, or let Submit run it first. See Prepare.
  3. Choose the engine and the force fields. The lists follow each other: an engine offers its force fields, a force field its waters. See Engines and force fields.
  4. Set the protocol with a preset, and change what you need. See Protocol and compute.
  5. Read the run plan and Submit. The run's folder is written, the job graph is queued, and the page moves to Runs.
  6. Follow it on Runs. The tiles and the trajectory appear when the analysis job has run, the MM-GBSA table when its own job ends. Then Report and Video. See The Runs screen and Reports and media.
